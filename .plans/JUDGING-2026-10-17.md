## The defect every hands-on judge hit (fixed)

The default Qualify request, which uses the LLM ClauseParser, crashed on 3 of the 4 sample tenders. The 4th
returned BID where the right answer is NO-BID. These errors had four causes:

- The LLM invented an `options` key, which the strict `qualify_clause` check rejected.
- It wrote "roads" as a category, which was ambiguous.
- It put two ISO standards in one clause.
- It read "₹240 Cr in each of" as an average, and read "₹75 Cr" as ₹750 Cr.

The bad parse was also cached, and the half-built case broke every later ripple, including resolve, which
returned a 500.

**Fix:**

- Sample tenders with unedited text use their vetted clauses.
- LLM clauses are mapped onto the engine's schema and then dry-run against the graph.
- When the LLM and the rule parser disagree on an amount, the rule parser's reading wins.
- A clause that still can't be read falls back to the rule parser, or becomes DECLARE. It never aborts the case.
- `blast_radius` skips clauses it cannot re-check.

**Verified:**

- All 4 tenders on the default path give their scripted verdicts.
- Edited text through the LLM path no longer crashes and gets the right verdicts. Buildings is now NO-BID.
- The full chain works: qualify → DEMO-0 → DEMO-1 → BID flips to NO-BID.
- A regression test replays the judges' exact bad LLM output.

## Other judge findings fixed

- **The Ask agent made up "why we believe" answers.** New tool `fact_history`: competing claims with
  document and page, plus the decisions (policy, decider, learned rule) that settled them.
- **The bus-factor ranking depended on the sampling seed past rank 2.** It is now averaged over 32 seeded
  `algo.betweenness` runs. Two disjoint seed sets give the same top 6, and the top 3 match exact Brandes.
- **MCP errors were opaque** ("Error executing tool X"). They now return the exception message, and all
  25 MCP tools carry the read-only annotation (`readOnlyHint`).
- **The README said vector RAG "confidently says the wrong thing".** On the hero question it abstained,
  so the wording was corrected.

## Still costing points (not fixed)

- **Fixed pipeline:** four of the six agents are deterministic, and none plans or negotiates (T1, T2).
- **The Q&A agent adds filters nobody asked for:** in one T1 ask, a "Prime" role and a years filter cut the
  answer from ₹2.10 B to ₹0.42 B. There is no self-check.
- **Demo LLM pool:** latency of 3 to 62 s under Groq rate limits, and the model switches step to step, so it
  is not the benchmarked Qwen3-32B.
- **Memory is per session (24 h).** There is no opt-in "promote to company memory". Conversation recall is
  the last 6 turns, and the MENTIONS edges are never read.
- **Benchmark caveats:**
  - Q333 gold is the engine the tools mirror.
  - GraphRAG-SDK was run without an ontology.
  - Single runs.
  - The 144/144 team score was tuned on the test set. All of this is disclosed, but the disclosures sit
    below the headline.
- **Graph-algorithm depth:**
  - `communities` returns one block.
  - WCC is used as a degree-0 check.
  - Most Cypher is 1-2 hops, with Python composing the rest.
- **Blog:** no images, no FalkorDB code recipes (prove_absence Cypher, the algo calls), no TL;DR.
